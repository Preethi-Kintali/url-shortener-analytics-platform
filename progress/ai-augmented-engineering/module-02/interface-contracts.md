# Module 02 FIX: Formal Interface Contracts & Boundary Alignment

## 1. Architectural Decision: Where Does the Fix Belong?

### The Decision:
The fix belongs fundamentally in **Task 1's specification and interface contract**:
- **Why:** In real applications, a "team" without an initial membership relationship cannot enforce tenant boundaries, access control, or administrative ownership. Decoupling the team creation from the creator's initial membership produces orphaned teams or forces brittle secondary migrations.
- **Action Taken:**
  1. Task 1 explicitly produces both `Team` and `TeamMember` relational models and the `TeamRole` enum in a single atomic database migration.
  2. Task 2's prompt receives the exact Prisma schema definition generated by Task 1 as an explicit input contract, eliminating any guesswork regarding table existence or delegate names.

*Where they agree:* Both tasks agree that `ownerId` on `teams` designates creator provenance, while `team_members` with `role: 'OWNER'` establishes authorization context.

### Contract 3: Task 5 (Invitation Schema) $\longrightarrow$ Tasks 6 & 7 (Dispatch & Acceptance)
```typescript
// SHARED LIFECYCLE CONTRACT:
export enum InvitationStatus {
  PENDING = 'PENDING',
  ACCEPTED = 'ACCEPTED',
  REVOKED = 'REVOKED',
  EXPIRED = 'EXPIRED',
}

// TOKEN CONTRACT (Task 6 Dispatch -> Task 7 Accept):
// 1. Dispatch generates raw crypto token: const rawToken = crypto.randomBytes(32).toString('hex');
// 2. Database stores SHA-256 hash: const tokenHash = crypto.createHash('sha256').update(rawToken).digest('hex');
// 3. Email link sends rawToken: https://app.knack.io/invitations/accept?token={rawToken}
// 4. Acceptance hashes caller's raw token and performs atomic transaction:
export interface AcceptInvitationContract {
  tokenHash: string;
  claimingUserId: string;
  claimingUserEmail: string;
  atomicOperations: [
    "Verify invitation status == PENDING and expiresAt > now()",
    "Verify invitation email matches claimingUserEmail (or claim allowed)",
    "Update invitation status = ACCEPTED",
    "Insert into team_members (teamId, userId, role)"
  ];
}
```
*Where they agree:* Tokens are never stored in plaintext in the database (mitigating database snapshot leaks), and state transitions are strictly serialized within an atomic transaction.
